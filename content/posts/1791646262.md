### It’s preety recent that tauri apps specially built as appimages are not working on modern linux distributions, like fedora, ubuntu, arch.

Appimages are one of the nicest way to distribute your app but not being able to run that is a bad thing. Appimages as a format is crucial for users who want to test your app and use them without the need of installing. Appimages are cool as they comes with all the required dependencies and can be operated  on systems such as Windows with WSL2 and FreeBSD with the Linuxulator.

This is a sample app image for a tauri based rest api client yaak.

So, I was building drawx the offline version of drawy. which gives data sovereignty. but drawx app image was not working on my machine due to some wayland related issues and not bundling the package with required c libraries and disabling using xorg just for running an app image is something no one is going to do. And tricking the app image with some environment variables is not a solution it’s a workaround which have not worked for me setting `WEBKIT_DISABLE_DMABUF_RENDERER=1` or `WEBKIT_DISABLE_COMPOSITING_MODE=1` is crashes on launch or displays a blank screen, never worked for me .. the issue is lack of libc libraries like lib\_wayland.so in the appimage itself.

Appimages are self contained in nature and requires no root access.

Download the appimage and make it executable and that’s it. the app should be working normally. All reasonable dependencies should be prepacked into the binary.

The issue with tauri is it’s not supplying the required libc modules.
